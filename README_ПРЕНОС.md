# Пренос на SLiMS на друг компютър (с инсталиран Docker)

Всичко необходимо е в **тази папка**. Базата (структура, настройки, българският
интерфейс по подразбиране) е в `install/full_dump.sql`, който се зарежда автоматично
при първо стартиране. Той е **без книги**. Вариантът с демо каталог е
`install/full_dump_with_demo.sql` (виж края на файла).

## Какво трябва да има на новия компютър
- Docker Desktop (или Docker Engine) + Docker Compose — това е всичко.
- Свободни портове **8881** (уеб) и **3307** (база). Ако са заети, смени ги в `.env`.
- За публичен достъп: свободни портове **80** и **443** (nginx).

## Стъпки
1. Копирай цялата папка `slims9_bulian` на новия компютър (напр. чрез USB или архива
   `slims-transfer.tar.gz`). Папката `.git` НЕ е нужна.
2. Увери се, че файлът **`.env`** е копиран (той съдържа портовете и паролата за базата).
   Ако липсва, копирай `.env.example` като `.env`.
3. В папката изпълни:
   ```bash
   docker compose up -d --build
   ```
   Първият път ще изтегли образите и ще билдне (няколко минути).
4. Отвори в браузъра: **http://localhost:8881**
   - Служебен вход: **http://localhost:8881/index.php?p=login**

## Данни за вход
При първо стартиране системата **генерира нова случайна admin парола** и я изписва в
логовете. Вземи я с:
```bash
docker compose logs slims | grep -A2 "ADMIN CREDENTIALS"
```
Потребител: `admin`. Смени паролата след първо влизане (Система → Библиотекари и потребители).

## Управление
```bash
docker compose stop      # спиране (данните се пазят)
docker compose up -d     # пускане
docker compose ps        # статус
docker compose down      # спира и премахва контейнерите (данните в volume се пазят)
docker compose down -v   # ВНИМАНИЕ: трие и данните (връща до демо състоянието от дъмпа)
```

## Публичен достъп: https://hrabarsko.hopto.org (nginx + Let's Encrypt)
`docker compose up -d` пуска и две допълнителни услуги:
- **nginx** (`slims-nginx`) приема портове 80 и 443. Порт 80 пренасочва към HTTPS,
  а 443 препраща към SLiMS. Конфигурацията е в `docker/nginx/` и следва модела на
  `/Volumes/storage/projects/docker/nginx` (ограничения на скоростта, защита от
  Slowloris, блокиране на скенери, лимит 10 опита за вход в минута на IP).
- **certbot** (`slims-certbot`) издава безплатен Let's Encrypt сертификат при първо
  стартиране и го подновява автоматично. Докато сертификатът не е издаден, nginx
  използва временен самоподписан и браузърът показва предупреждение.

Изисквания:
1. DNS записът `hrabarsko.hopto.org` в No-IP сочи към публичния IP на мрежата.
   При динамичен IP го обновявай с No-IP клиента (DUC).
2. На рутера портове **80** и **443** (TCP) са пренасочени към локалния IP на този
   компютър. Без това Let's Encrypt не може да провери домейна.
3. В `.env`: `DOMAIN=hrabarsko.hopto.org`. По избор `LE_EMAIL=` за известия при
   проблем с подновяването.

Проверка:
```bash
docker compose logs certbot            # издаден ли е сертификатът
docker compose logs nginx | grep ssl   # кой сертификат е активен
docker compose logs nginx | grep BLOCKED   # блокирани скенери
```
След издаването nginx сам зарежда новия сертификат до една минута.

Бележки:
- В SLiMS (Система → Настройки) НЕ включвай „HTTPS“ (`https_enable`). HTTPS се
  прекратява в nginx; настройката в SLiMS би довела до безкрайно пренасочване.
- Директният достъп през http://localhost:8881 продължава да работи.
- Блокиране на IP адрес: добави `deny <IP>;` в `docker/nginx/blockips.conf` и
  изпълни `docker compose exec nginx nginx -s reload`.

## Чиста инсталация без демо данни (по избор)
В `docker-compose.yml`, в услугата `db`, коментирай реда с `full_dump.sql` и
разкоментирай двата реда с `senayan.sql` и `sampledata.sql`. После `docker compose down -v && docker compose up -d --build`.
Българският интерфейс остава (файловете са в `lib/lang/locale/bg_BG/`), но езикът по
подразбиране за служебната част ще е английски — сменя се от Система → Настройки или
чрез падащото меню за език на екрана за вход.

## Какво е включено (мои промени спрямо оригинала)
- Поправка в `Dockerfile` (права за папка `config` — иначе SLiMS дава грешка 500).
- Български превод: `lib/lang/locale/bg_BG/` + регистрация в `sysconfig.inc.php`.
- `install/full_dump.sql` — ЧИСТА база (без демо книги): празен каталог, готова
  конфигурация (типове колекции, локации, правила за заемане), български език по
  подразбиране. Демо версията с примерните книги е запазена като
  `install/full_dump_with_demo.sql` (за да я използваш, преименувай я на `full_dump.sql`).
- Обратно прокси nginx + Let's Encrypt: `docker/`, услугите `nginx` и `certbot` в
  `docker-compose.yml`, Apache настройки за прокси в `Dockerfile`, `config/url.php` от `entrypoint.sh`.
- Сайт на НЧ „Просвета 1925“ – с. Храбърско (виж долу).

## Сайтът на читалището: какво къде се сменя
Публичната част е пригодена за читалището и неговата библиотека.

| Какво | Къде |
|---|---|
| Адрес, телефон, e-mail, работно време, координати, описание за търсачки, текст във футъра, карта, Facebook | Администрация → Система → Шаблон → „Персонализиране“ (стойностите по подразбиране са в `template/default/tinfo.inc.php`) |
| Страниците „Читалището“ (`chitalishte`), „Село Храбърско“ (`selo`), „Библиотеката“ (`libinfo`), „Контакти“ (`kontakti`), „Как да търся“ (`help`), приветствието на началната страница (`headerinfo`) и новините | Администрация → Система → Съдържание |
| Снимки в карусела | всички `.jpg` в `template/default/assets/images/prosveta/slides/` (по азбучен ред, ~1800×790 px) |
| Лого, favicon, изображение при споделяне (`og-image.jpg`, 1200×630) | `template/default/assets/images/prosveta/`, `favicon.*`, `apple-touch-icon.png`, `site.webmanifest` в корена |
| Началното съдържание (име, страници, новини) | `install/prosveta_1925.sql` – зарежда се сам при нова инсталация. При повторно изпълнение презаписва тези страници. |

Промените по файловете влизат в сила след `docker compose up -d --build slims`, защото кодът е вграден в образа.
Промените през администрацията важат веднага.
